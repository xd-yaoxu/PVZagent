# 新增需求：决策侧边栏与战术时间轴

需求来源：2026-10-21 用户在本聊天中提出。状态：已纳入需求与开发安排，界面和分段功能尚未实现。

## 目标

游戏正常进行时，能看懂 Agent 当前关注的局势、正在推进的目标、准备执行的动作及结果。一局结束后，通过战术片段理解布局如何从经济建设发展到防线扩展和收尾。

这两项属于第一版交付范围。保持已确定的原版 3-7、十卡槽环境、截图感知和异步实时运行要求。

后续测试新增“失败归因面板”，作为右侧栏的赛后复盘视图，接收用户提供的失败录屏，将失败表现与上游战术、感知、调度、执行及环境因素分层关联。点击原因查看视频时间戳、关键帧及已对齐的时间轴事件；缺失内部日志时标记推测／待确认。详细输入、层级、证据、改进复测及验收见 `失败归因面板.md`，目前尚未实现。

## 决策侧边栏

默认在游戏右侧使用独立窄面板，提供折叠。面板不遮挡游戏检测区域；空间不足时先折叠，不擅自改变已选定的游戏窗口大小和缩放。布局是否容纳得下，在第 3 天采集真实窗口尺寸后检查。

### 显示内容

| 区域 | 内容 |
| --- | --- |
| 当前状态 | 观察中、等待模型、建议已返回、校验中、执行中、验证结果、应急接管等真实状态；模型等待时显示已用时间 |
| 当前战术片段 | 片段名称、开始时间、当前目标；暂定阶段明确标注“暂定” |
| 目标侧重 | 当前阶段的重点、正在执行的具体目标，以及因紧急威胁临时调整的简短理由 |
| 布局偏好 | 低威胁时尽量对称、整齐、分区清楚；必要时说明为守线暂时打破对称的取舍 |
| 局势摘要 | 截图可支持的资源、防线缺口和当前威胁，附观测时间；不确定项显示未知／低置信度 |
| 下一步动作 | 植物、目标位置或收阳光动作；显示计划状态，执行后显示真实结果 |
| 简短理由 | 模型显式输出的可读决策摘要，通常 1—3 句话，说明与当前目标有关的依据 |
| 决策历史 | 时间、简短理由、动作、来源和结果，可展开对应截图 |

“思考过程”以模型公开输出的决策摘要呈现，不读取或要求模型内部隐藏推理。模型尚未返回时只展示真实等待状态和已有观测，不编造它正在考虑的内容。公开摘要和动作由同一条带 ID 的模型输出关联，不能事后用另一段文本冒充当时理由。

动作来源区分 LLM、应急规则和用户操作。被拒绝、已过期、取消或执行失败的建议仍保留真实状态；模型返回文本不等于动作成功。

历史记录采用有界显示和本地日志，避免逐帧刷满面板。重要威胁、阶段变化与动作结果优先展示。

## 战术时间轴

在侧栏下部显示当前局的可滚动纵向时间轴。每个片段是一张可点击卡片，宽度适合侧栏；整局结束后沿用同一数据做复盘。

### 片段内容

每个片段至少显示名称、开始／结束时间、目标、关键事件、主要动作及结果。点击后展示对应截图、当时的决策摘要与执行记录。当前片段以“进行中”结束时间显示；重开创建新的一局，历史记录单独保留。

### 初始阶段词表

| 阶段 | 判断依据示例 | 主要关注 |
| --- | --- | --- |
| 开局经济期 | 开局后以经济植物投入和基础资源积累为主 | 经济布局与最低限度防守 |
| 前期发育期 | 出现首批威胁，开始建立各行基础输出 | 补足缺口并维持发展 |
| 中期转型期 | 基础经济和输出形成，扩大水域防线、补阻挡或升级输出 | 从基础布局向可持续防线调整 |
| 后期收尾期 | 进入后续／最后波次，主要动作转为守线、补损和结束战斗 | 处理威胁、维持防线 |

这些是初始语义标签，不保证每局都完整、顺序一致或边界清晰。同一阶段可再次出现；没有转型证据时不强行创建“中期转型”。信息不足时使用“阶段待确认”，短时紧急威胁作为片段内事件记录，不必把整局切得很碎。

选卡、菜单和奖励界面使用独立的场景标记；“最后一波”仅是事件，不能直接认定已经通关。

### 阶段必须影响决策

用户追加要求：开局重发育，前期发育和减压并行，中期重阵型建设，后期保护已有阵容不被突破。各阶段目标偏好进入实际 LLM 请求，侧栏显示当前重点；临时目标变化关联时间轴事件。详细目标、应急取舍和验收见 `分阶段战术目标.md`，配置见 `../config/tactical-priorities.json`。

### 分段原则

1. 根据经济植物与输出布局、资源变化、威胁、波次提示和实际动作的持续变化提出阶段候选。
2. 候选经多次可靠观察后确认，合并过短／重复片段；阈值待实际运行测量，不按固定分钟强行切换。
3. 在线分段只使用截至当前的观测。结束后可提供标有“复盘修订”的版本，保留在线原始边界，避免用后续结果改写当时判断。
4. 一个主片段覆盖一个时间区间，主片段之间不重叠、不留无标记空档。事件、动作及图片可有多个，但都能追溯到原始时间和 ID。

时间轴默认使用本局单调时钟的相对经过时间，记录为 `00:00` 等；不是从截图臆测出来的游戏内部时钟。人工打开菜单或画面不可见时保留时间区间并标注场景／数据缺口。录像导入则使用视频时间，明确标记其来源。

## 数据关联

| 对象 | 最小字段 |
| --- | --- |
| 对局 | `run_id`、开始时间、时钟来源、环境版本、结束状态 |
| 观测 | `state_id`、`capture_time`、截图引用、可见状态、置信度 |
| 决策摘要 | `decision_id`、`request_id`、所用 `state_id`、目标、公开简短理由、拟执行动作、返回时间 |
| 动作与结果 | `action_id`、所属决策、来源、开始／完成时间、校验状态、视觉验证结果 |
| 战术片段 | `segment_id`、类型、开始／结束时间、暂定／确认状态、切换依据、观测与事件引用 |

先记录这些关联字段，侧栏、时间轴和复盘共用数据，避免展示与实际操作对不上。具体字段约束随第 9—12 天的决策／执行接口实现。

## 融入现有开发顺序

| 时间 | 本次需求带来的工作 |
| --- | --- |
| 第 3 天 | 标定游戏窗口时检查右侧可用空间；不在此阶段提前做完整面板 |
| 第 6—8 天 | 观测、事件和动作日志带本局相对时间及唯一 ID，准备后续可视化数据 |
| 第 9—12 天 | 将阶段与目标偏好接入 LLM 请求；结构化输出包含当前目标、动作及公开简短理由，关联真实执行结果；保持异步运行 |
| 第 17 天 | 在原定战术面板任务中实现决策侧栏和时间轴基础视图，接入真实日志 |
| 第 18—20 天 | 完善阶段分段、选择片段看证据、模式切换标记与复盘；沿用原计划的交互和证据复盘任务 |
| 第 21 天 | 将侧栏和时间轴纳入功能冻结前的回归验收 |

先实现纵向时间轴和有证据的摘要，不额外增加多窗口工作台或视频剪辑系统；阶段边界准确性需要实机数据校准。

## 验收条件

- [ ] 游戏进行和模型等待期间，侧栏状态更新不阻塞感知／执行。
- [ ] 侧栏每条摘要、动作与结果可通过 ID 对齐，过期和失败不显示为成功。
- [ ] 当前战术阶段可见，阶段名称和切换依据能关联真实观测；未知状态如实展示。
- [ ] 阶段目标实际参与模型决策，侧栏显示重点和临时改目标的理由，时间轴保留目标变化事件。
- [ ] 每局有连续的片段时间轴，可展开截图、关键事件和决策结果。
- [ ] 重开后时间和片段使用新 `run_id`，旧局仍可复盘。
- [ ] 浏览历史仅切换面板内容，不暂停游戏、不改变 Agent 控制模式；需人工接管时走既有显式模式切换流程。
- [ ] 面板打开、折叠和点击历史不遮挡截图区域；实际面板接入后重测失焦行为。
- [ ] 人工录像示例与 Agent 在线输出明确标识，人工游玩不冒充模型决策日志。
