# 分阶段战术目标

来源：2026-10-21 用户追加要求。状态：已纳入第一版规格与配置，尚未接入实际 LLM 或执行循环。

## 目标

阶段识别必须影响 LLM 的真实决策目标，并同步体现在侧栏和时间轴。阶段标签、目标优先顺序、目标选择依据与执行结果应相互关联。

阶段目标是偏好顺序，LLM 仍根据当前资源、可用卡片、场地限制和威胁选择具体动作；不把偏好写成每局照抄的固定种植步骤。经济发展重点指可见的阳光资源与生产能力。

## 四个阶段的侧重

| 阶段 | 核心目标 | 次级目标 | 行动取舍示例 |
| --- | --- | --- | --- |
| 开局经济期 | 优先发展阳光生产能力 | 用足够低的投入处理早期威胁，保持后续发展空间 | 风险可控时投入经济；威胁接近而已有防线不足时先处理威胁 |
| 前期发育期 | 经济发展与减压并行 | 补上有威胁行的基础输出和必要阻挡，避免为单点过度投入 | 在继续补经济与为受压行补输出／应急解围之间，根据威胁紧迫程度取舍 |
| 中期转型期 | 建设完整、可持续的阵型 | 补齐各行、水域、阻挡与输出缺口，保持资源周转 | 基础经济能支撑发展时优先补阵型短板，而非继续无条件增加经济植物 |
| 后期收尾期 | 保护已有阵容，避免被突破 | 补损、保护关键输出、处理近身与特殊威胁，保留必要应急资源 | 威胁逼近或防线出现缺口时优先修补／解围，避免为边际经济收益延误处理 |

“够用的经济”“近身威胁”“阵型缺口”等判断依赖截图观测和后续实测，不预设固定向日葵数量、冷却秒数或资源配比。

## 低威胁时的对称与美观偏好

用户追加要求：威胁不大时阵型建设尽量对称，不要求绝对对称，但要保证美观。这是第一版的阵型偏好，适用于所有阶段的安全建设机会，中期阵型建设时尤其重视。

对 3-7 的默认解释是上下呼应、同类植物成列、前后层次清楚，水域与草地分别协调。上下对称以草坪中间的水平线为参考；不要求把承担不同作用的前后列做成左右镜像。精确行列数与镜像格映射在第 3 天标定后确定。

偏好应用顺序：

1. 先满足合法性、防突破、当前阶段的实质目标及必要资源预留。
2. 在威胁经可见证据确认较低、多个方案都满足上述条件时，优先选择布局更协调的方案，如同类植物对齐、上下对应位置互相呼应、经济／输出／阻挡分区清楚。
3. 不同路威胁、水陆地形、可用植物、冷却和资源可使对应行采用不同布局；保留合理的不对称。
4. 威胁上升时允许立即打破对称。局势稳定后，结合后续正常建设或补损逐步改善布局；不为追求镜像额外铲除有效植物、反复重种、花空应急资源或延误防守。
5. 威胁信息不确定时不把它当作低威胁。若没有必要建设或补损机会，可以等待，不为“补齐外观”强行种植。

美观暂不采用武断的固定分数、相同植物数量或绝对镜像约束。先以可见的行列对齐、功能分区和上下均衡作为偏好依据，后续用用户反馈校准。

决策摘要可说明“低威胁，选择与相邻／对应行对齐的位置”，或“受压行先补防，暂时保留不对称”。侧栏和时间轴记录实际取舍，不能只显示美观标签而不影响候选位置选择。

## 跨阶段原则

1. 合法性、真实资源、卡片状态和动作新鲜度始终优先校验；阶段偏好不能使非法操作变合法。
2. 紧急威胁可临时提高防守／解围目标优先级。它作为当前阶段内的目标调整事件，不自动把战术阶段改成“后期”。
3. 阶段或局势证据不足时使用“阶段待确认”，先补充观测并处理明确风险，避免凭猜测做高投入动作。
4. 威胁解除后重新评估原阶段目标，不永久停留在应急行为，也不强制补回先前取消的动作。
5. 阶段变化后，返回的旧决策需重新检查局部前提和目标适配性；阶段编号变化本身不等于所有旧动作无效。应急处置已经改变局势时，旧经济计划不能绕过检查直接执行。
6. 对称与美观低于生存和阶段实质目标；只在证据支持的低威胁、资源允许且不损害关键功能时参与布局选择。

## 决策循环中的使用

1. 形成带时间戳的最新可见状态与阶段估计，给出可信度及证据引用。
2. 将阶段、目标偏好、当前显著威胁、合法动作约束和用户目标一起传给 LLM；低威胁时同时提供对称／整齐偏好与可用位置。LLM 明确选择本次目标、动作及公开简短理由。
3. 执行前使用新观测复查资源、卡片、目标位置、威胁及本次目标的适用性。
4. 根据动作后截图记录实际结果，必要时重新规划。
5. 侧栏显示当前阶段、当前重点目标、临时改目标的简短理由及结果；时间轴将同一片段内的目标变化作为事件保存。

请求与日志至少关联：`run_id`、`state_id`、`phase`、`phase_confidence`、`priority_profile_version`、`active_goal`、`goal_change_reason`、`evidence_refs`、`decision_id`、`action_id`。`goal_change_reason` 使用公开简短摘要，不索取内部隐藏推理。

## 展示示例

以下是说明交互的假设例子，不是已运行的模型日志，也不是对用户录像的决策转录：

> 当前阶段：开局经济期。当前重点：发展阳光生产。调整：第 2 行威胁已经接近缺口，先解围，安全后恢复经济建设。

> 当前阶段：后期收尾期。当前重点：保护关键防线。调整：优先补齐受损行的阻挡和输出，暂缓新增经济投入。

时间轴点击该事件时，能看到引发调整的当时截图、被选动作及实际结果；不能用最终通关结果替代当时证据。

## 实现与验收安排

- 第 6—8 天：观测、威胁和布局事件日志为阶段估计提供依据。
- 第 9 天：在 LLM 输入中接入阶段和偏好配置，结构化输出中加入本次目标及公开理由；不等到界面开发时才影响决策。
- 第 10—12 天：结合最新状态检查目标是否仍适用，记录目标调整和动作结果。
- 第 16 天：纳入战局题，检查无紧急威胁时的四阶段侧重，以及开局遇到近身威胁时能否先解围。阶段设置应与题目状态相容，不用互相矛盾的输入强行诱导区别。
- 第 17—20 天：侧栏和时间轴展示同一套阶段、目标和结果数据。

验收重点：

- [ ] LLM 实际请求包含阶段目标配置，每次输出明确本次目标，展示内容与请求／动作记录一致。
- [ ] 无紧急威胁且存在发展机会时，开局能优先经济；前期兼顾发育与减压；中期补齐阵型；后期保护防线。
- [ ] 任意阶段出现明确突破风险时，允许先解围，并记录目标调整理由；风险降低后恢复评估。
- [ ] 资源不足、卡片不可用、格子状态不符或决策过期时，阶段目标不能绕过执行校验。
- [ ] 阶段不确定时如实显示，不编造高置信度标签；目标不会因短暂误检反复抖动。
- [ ] 保留失败案例：若阶段判断或目标选择不合适，复盘能定位当时证据与动作，不事后改写为正确决策。
- [ ] 在低威胁且功能／资源相当的候选布局中，能优先选择上下协调、同类对齐和功能分区清楚的位置。
- [ ] 相同布局出现紧急威胁时，能够舍弃外观优先补防；地形和威胁差异允许合理不对称。
- [ ] 不为美观进行无必要铲除重种、额外投入或延误守线；侧栏可说明保持或暂时打破对称的简短依据。
